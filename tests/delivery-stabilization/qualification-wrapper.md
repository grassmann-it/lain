# Strict exact-Core qualification wrapper

`qualification_wrapper.py` consumes already produced evidence. It never builds,
executes Core/.NET/Go, starts a service, invokes a provider or touches installed
state. Its only child commands are read-only `git show` and `git ls-tree` for
explicitly pinned source commits. Root reviews the source and concrete artifacts
before use.

All input paths are explicit; input SHA-256 pins are mandatory. Choose a new
absolute output path. No pass artifact is written on validation failure, and an
existing output is never overwritten. A passing wrapper emits the publisher's
required `passed: true`, `sha256`, `sourceManifestSha256`, plus the application
source commit, separate Go unit source commit, build/prepared hashes, all raw
report hashes and scope/limitations. It never reads or copies old
`proxy/qualification.json` flags.

```sh
python3 tests/delivery-stabilization/qualification_wrapper.py \
  --repository /absolute/frozen-checkout \
  --source-commit FULL_FINAL_APPLICATION_COMMIT \
  --go-unit-source-commit FULL_REVIEWED_GO_UNIT_COMMIT \
  --core /absolute/frozen/lain-proxy --core-sha256 CORE_SHA256 \
  --build-manifest /absolute/frozen/lain-proxy.manifest.json --build-manifest-sha256 BUILD_SHA256 \
  --source-manifest /absolute/frozen-checkout/proxy/source-manifest.json --source-manifest-sha256 SOURCE_SHA256 \
  --prepared-manifest /absolute/prepared/prepared-manifest.json --prepared-manifest-sha256 PREPARED_SHA256 \
  --upgrade-report /absolute/upgrade/qualification.json --upgrade-report-sha256 UPGRADE_SHA256 \
  --process-report /absolute/process.json --process-report-sha256 PROCESS_SHA256 \
  --providers-report /absolute/cohere-kilo.json --providers-report-sha256 PROVIDERS_SHA256 \
  --context-report /absolute/context.json --context-report-sha256 CONTEXT_SHA256 \
  --archive-report /absolute/archive.json --archive-report-sha256 ARCHIVE_SHA256 \
  --go-unit-report /absolute/journal-segments/unit.json --go-unit-report-sha256 UNIT_SHA256 \
  --output /absolute/new/qualification.json
```

The six mandatory top reports are generated by:

- `tests/backend/upgrade_gate.py`, including **all eight** checks: original
  protocol/durability, independent authentication/crash, Inspector, upgrade
  boundaries, native tool exclusion, actual Hostwriter transports, mixed-version
  transition and ten SQLite consumer replays. The eight sibling child reports
  are also read, validated and hashed. Summary-to-filename mapping is fixed,
  including `consumer-replay-10` → `consumer-replay.json`. Every other child has
  its exact gate's check identities; Inspector uses `case`, the other gates use
  `name`. Missing/duplicate names, substituted same-count reports,
  failed/nonboolean `passed`, hidden inner failures and mismatched binary
  identities are refused.
- `tests/core-stabilization/process_probe.py`, all six actual Core cases with
  unchanged binary and private-loopback isolation evidence.
- `tests/providers-cohere-kilo/gateway_probe.py`, all twenty-seven synthetic
  Cohere/Kilo cases: the existing nineteen Chat transport/refusal/cancellation/
  truncation cases plus eight Cohere Responses cases, with exact keys
  `responses_json`, `responses_stream`, `responses_tool`, `responses_store_true`,
  `responses_previous_response_id`, `responses_native_search`,
  `responses_additional_native_search`, `responses_native_file_search`.
  A historical nineteen-case report cannot qualify this source.
- `tests/model-compatibility/context_boundary_probe.py`, twelve protocol/
  streaming/status combinations plus both bounded-diagnostic cases.
- `tests/core-stabilization/archive_gate.py`, all twelve archive/process/real
  collector and matching-snapshot cases. Explicit old-binary/full-Host lifecycle
  limitations remain in the wrapper's scope record.
- `tests/core-stabilization/evidence/journal-segments/unit.json`, with actual
  zero exit code, the full unfiltered prepared-adapter Go command, matching
  source/prepared pins, all three Go packages and exactly the two required
  `python3 -m unittest discover -s tests/acceptance -p test_upgrade_probe.py -v`
  and `python3 -m unittest discover -s tests/delivery-stabilization -p test_legacy_rollback.py -v`
  commands. They map respectively to `upgrade-tests.txt` and `legacy-tests.txt`;
  command duplication or arbitrary exit-zero substitutes are refused.
  The sibling `go-test.jsonl`, `upgrade-tests.txt` and
  `legacy-tests.txt` must match its raw hashes. Raw Go failures, missing package
  passes, test-count disagreements and skips other than the optional bounded
  growth measurement are refused. Each Python summary must match the exact last
  500 characters of its assigned raw log (the current producer's schema). Its
  log must identify the expected test module and a successful unittest summary
  with at least twelve Upgrade or ten Legacy tests. Swapped logs are refused even
  when their supplied hashes and summary tails have been updated.

An external reviewed hash is mandatory for each top report. Upgrade child and
Go raw-file hashes are derived from the observed files, recorded in the wrapper
and rechecked before sealing; they are not cryptographic signatures or proof of
an untrusted report producer. A producer's successful assertions are evidence,
not replaced by inventing a new qualification flag. Root reviews the actual
artifacts and their producer/source identities separately.

## Separate source identities

Go unit source `6adbf89624b7afc631ca5dcc9261e479a18ef518` may precede the final
application commit. The wrapper does not relabel those tests with a later commit
or require the commits to be equal. It requires both commits to contain the
**identical pinned `proxy/source-manifest.json` bytes**, checked through Git.
At each commit it also compares every `buildInputs` blob to its declared hash
and requires the complete contractual input set: all regular files below
`proxy/adapter` and `proxy/patches`, plus the six fixed upstream/license/toolchain/
build-preparation inputs from `prepare-core.verify`. Extra, missing, changed,
symlink or submodule inputs are refused. A later adapter change with a stale
unchanged manifest therefore cannot inherit the earlier Go pass.
The Go report must name its explicit earlier commit and exact prepared-manifest
hash. A changed Core source manifest requires a matching new Go report.

The build sidecar must bind the candidate Core bytes and source-manifest hash,
compiler, upstream commit/version/archive, patch-set identity and modification
flag. Prepared SDK source provenance has a separate explicit hash and must bind
the same source and upstream/patch identity. The wrapper validates that inventory
metadata; it neither regenerates nor executes the prepared SDK source tree.

Some existing process schemas contain only `coreSha256`, without a source hash.
They are bound to the source via the exact candidate binary and checked build
sidecar. Output records their missing direct source hash as null; it does not
pretend the raw schema reported one. Any source hash actually present in a raw
report must match. Nullability here is provenance coverage, not success inferred
from absent metadata.

## Bounded source fixtures

After Root releases the serialized slot:

```sh
python3 tests/delivery-stabilization/test_qualification_wrapper.py
```

Fixtures use disposable JSON/log files, a nonexecutable synthetic Core payload
and a temporary Git repository. They cover distinct application/Go commits with
the same manifest, missing reports, bad source/binary/build/prepared/report pins,
strict passed types, incomplete/duplicate upgrade children, hidden child failures,
raw Go failures, changed manifest lineage, lost context/archive cases, filtered
unit commands, report/command/log substitution, stale-manifest adapter changes
or added/removed inputs, and duplicate JSON keys. They never execute product binaries,
SDKs, services or providers. Source preparation is not an executed test result.

The resulting wrapper qualifies synthetic Core boundaries only. Live providers,
real OAuth rotation, exact-package/Desktop/native acceptance, installation,
arbitrary schema rollback and uninterrupted in-flight live updates remain
separate. Publication still validates that its freshly built Core is byte-identical
to this qualification; a different rebuilt binary must not inherit this pass.

## Candidate build and artifact order

These are commands for Root's later serialized slot, not actions performed by
this handoff. Use a final committed checkout containing the Usage helper fix
`9d4f708` and the twenty-seven-case provider probe. Run with the existing bounded
compiler scope and a fresh SSD `TMPDIR`. `LAIN_DELIVERY_RUN`, `LAIN_USAGE_DLL`
and `LAIN_HOST_EXPORTER_DLL` below must be explicit absolute paths. The two DLL
inputs must be freshly built from that checkout with adjacent runtimeconfig,
deps and dependencies; the Usage executable must support both `--ingest-journal`
and `--collect-journal`. A cleaned historical binary is not an available input.

```sh
python3 scripts/build-core-verify.py
TMPDIR="$LAIN_DELIVERY_RUN/tmp" \
  LAIN_GO=/home/tomka/.local/share/model-usage/toolchain/go/bin/go \
  GOMAXPROCS=2 GOMEMLIMIT=1GiB \
  scripts/build-core.sh "$LAIN_DELIVERY_RUN/core/lain-proxy"
```

Retain candidate Core and its adjacent `.manifest.json`; compute/review their
hashes together with `proxy/source-manifest.json`. Define `LAIN_CORE_SHA` and
`LAIN_CORE_SOURCE_SHA` from those exact bytes. Every process gate below must run
inside its own loopback-only user/network namespace. This shell helper has no
fallback to the user's network:

```sh
lain_private_net() {
  unshare --user --map-root-user --net -- sh -c 'ip link set lo up && exec "$@"' sh "$@"
}
lain_private_net python3 tests/backend/upgrade_gate.py \
  --core "$LAIN_DELIVERY_RUN/core/lain-proxy" --consumer "$LAIN_USAGE_DLL" \
  --host-exporter "$LAIN_HOST_EXPORTER_DLL" --dotnet /usr/bin/dotnet \
  --baseline-core /home/tomka/Desktop/lain/artifacts/lain-linux-x64-gateway-quota-state-20261025/proxy/lain-proxy \
  --output "$LAIN_DELIVERY_RUN/upgrade"
lain_private_net python3 tests/core-stabilization/process_probe.py \
  --core "$LAIN_DELIVERY_RUN/core/lain-proxy" --report "$LAIN_DELIVERY_RUN/process.json"
lain_private_net python3 tests/providers-cohere-kilo/gateway_probe.py \
  --core "$LAIN_DELIVERY_RUN/core/lain-proxy" --report "$LAIN_DELIVERY_RUN/providers.json"
lain_private_net python3 tests/model-compatibility/context_boundary_probe.py \
  --core "$LAIN_DELIVERY_RUN/core/lain-proxy" --report "$LAIN_DELIVERY_RUN/context.json"
lain_private_net python3 tests/core-stabilization/archive_gate.py \
  --core "$LAIN_DELIVERY_RUN/core/lain-proxy" --core-sha256 "$LAIN_CORE_SHA" \
  --source-manifest-sha256 "$LAIN_CORE_SOURCE_SHA" --usage-helper "$LAIN_USAGE_DLL" \
  --dotnet /usr/bin/dotnet --report "$LAIN_DELIVERY_RUN/archive.json"
```

Then run the fully pinned wrapper command above with these five process reports,
the existing reviewed Go unit report and its **exact matching prepared-manifest**,
all eight upgrade children and three Go raw files retained. Do not silently
substitute a new prepared manifest or relabel the Go source as the app source.
If the final Core source manifest changed since the Go unit gate, rerun that
unit gate on the new manifest instead of transferring its pass.

Finally, use two new absolute package directories:

```sh
scripts/publish-linux.sh --mode monitor "$LAIN_DELIVERY_RUN/package-monitor"
LAIN_QUALIFICATION_FILE="$LAIN_DELIVERY_RUN/qualification.json" \
  scripts/publish-linux.sh --mode gateway "$LAIN_DELIVERY_RUN/package-gateway"
```

The Gateway publisher rebuilds Core; it must match the wrapper's exact binary
and source hashes. Publication does not qualify the package or installed UI.
Afterwards the explicit d720→candidate four-package fixture, exact-package
private-Xvfb/native acceptance and independent installed preservation gates
remain mandatory before their corresponding delivery claims.
