# Host worker planning (offline)

Serial lane command from the repository root:

```sh
dotnet run --project tests/workers-host/WorkersHost.Tests.csproj --no-restore
```

If the new project's assets have not been restored, the root serial lane must first run its normal restore step (or omit `--no-restore`). No new packages are required. This console suite uses isolated temporary state, synthetic credentials, the real compiler and Codex export, and one ephemeral loopback HTTP test server. It never contacts providers or invokes Codex, applies a profile, creates tokens, installs anything, or touches personal state.

Coverage includes strict HTTP/file JSON shape and duplicate keys; nulls, versions, identities, bounded batches and fields; literal relative write paths and cross-task collisions; ordered route IDs and exported aliases; actual exported reasoning defaults and exact supported efforts; unknown, hidden, disabled, out-of-profile and internal review routes; account eligibility; stale revisions/profile/application metadata; actual runtime route/transport/credential/cost drift; free-only already enforced in route or profile versus a hypothetical project override; sanitized distinct provider errors; caller-owned auth middleware; and read-only file preservation.

Integration needs `using Lain.Host.Workers; app.MapWorkerEndpoints();` after the existing management-auth middleware. The extension uses the already registered `OwnStatePaths`, `ModelsService`, `ProxyConfigurationWriter`, `ProviderCostPolicy` and `ProviderCatalogRegistry`; no worker service registration is required. HTTP errors use the existing flat `ApiError` contract. No `Program.cs` changes belong to this package.

Schema/contract version is 1. `MaxWorkers` is 1–12, with at most that many tasks per batch; setup accepts empty purposes/tasks. Purpose and route-list limits are 128, prompts 32768 characters, task write declarations 128 paths of at most 512 characters, and HTTP bodies 2 MiB. Keys are exact ASCII letter/digit/underscore/hyphen identities of at most 100 characters. Reasoning names are exact catalog choices, bounded to 32 characters. Write conflict comparisons conservatively ignore case for portable filesystems. Paths are declarations, not ACLs; the runner verifies native isolation and current installed profile before execution. A plan is not a credential, execution permission, quota reservation or hard spend cap.

Each resolved task appends `ModelCompatibilityDto? Compatibility = null` to the original constructor. The planner supplies actual route-scoped compatibility evidence from the existing compiler-backed catalog. Functions, streaming and tool continuation are required: an explicit `unsupported` value excludes that candidate from ordered planning, and an unsupported-only purpose returns `worker_capability_unsupported`. Unknown values remain unknown in the task evidence with precise task-specific advisory notes; they do not by themselves block execution or change declared route order. The current catalog leaves tool continuation unknown even for native Codex transports. That is an honest qualification limit, not a requirement for a new positive qualification store. Generic tool documentation and local client fixtures do not establish provider-tested acceptance. The parent executable runner rejects null reasoning effort, without inventing `none` or inheriting an unchecked global value. Unknown reasoning remains visible in read-only plans with an execution-blocked note. Compatibility identifies the route/provider, native client and actual compiled transport; note prose is explanatory, not an execution permission contract.

Fixture baselines use the real `codex-access-snapshot` credential kind with synthetic private material. Rejected account/mode/cost states are introduced through the repository only after valid baseline compilation, so fixture construction itself does not try to publish invalid inference state. All fixture writes stay inside fresh temporary roots.
