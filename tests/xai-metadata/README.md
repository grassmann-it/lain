# Explicit xAI team discovery

Source and fixtures prepared on `e48bc11`. **Not built or run by this worker**;
Root owns the serialized build/runtime slot and Program registration.

Production entry points:

- Account details and context menu: **Discover team**, xAI only, explicit click.
- `lain accounts discover ID --revision N --json` reads configuration first and
  sends that account's generation. No API key is entered or passed to the CLI.
- `POST /api/v1/accounts/{id}/metadata/xai` with
  `{ "revision": N, "value": { "expectedGeneration": G } }` returns existing
  `ConfigurationDto`; the request contains no credential.

The service reads a saved `inference` or `models` API-key projection, never a
quota-only management token. The sole remote operation is the existing fixed
`GET https://api.x.ai/v1/api-key`. It confirms only the returned team binding,
not quota, money, billing access, account health or a successful inference.
Missing identity and mismatches preserve the account. Matching already-confirmed
bindings do not increment configuration revision or account generation.

Root registration (the existing shared HTTP client must disable redirects):

```csharp
builder.Services.AddSingleton(sp => new XaiKeyMetadataService(repository, secrets,
    sp.GetRequiredService<AccountService>(), providerHttp, mutations));
// After builder.Build(), under the ordinary loopback/auth middleware:
app.MapXaiKeyMetadata();
```

The endpoint marks `OwnsPublicationGate`: the shared mutations gate is held only
while capturing the account/credential and while checking/publishing the response.
It is released during provider HTTP so account removal/reconnect can proceed.
Strict revision, generation, enabled/provider and selected-credential checks
prevent a late result from changing a removed, changed or retired target.
