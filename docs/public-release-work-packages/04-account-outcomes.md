## Outcome and ownership

client setup are configured/observed/unknown/unsupported, with a useful next action.
Own scoped account/outcome presentation modules and CLI shared presentation/tests;
existing MainWindow/AccountWizard shared edits integrated by00. Credential flows,
model reconcile and dependency removal remain their established domain owners.

## Tasks

- Read actual connection methods, account purposes and scoped observations.
  Saved credentials aren't successful auth; listed models aren't accepted access.
- Display a compact per-account outcome/source/freshness summary and best available
  qualified next action, preserving custom names and short provider defaults.
- Quota unavailable/unsupported is neutral. State Pro/OAuth required only from
  concrete checked product/plan evidence; don't invent a universal OAuth workflow.
- Offer existing supported login/monitor augmentation on the same account without
  duplicate identities. Monitoring alone doesn't configure inference or clients.
- Connect outcome links into existing route adoption, Apply/export preview and
  actual menu verification. Dependency-aware hide/disable/remove explains effects
  rather than a dead-end error; no automatic paid replacement/default choice.

## Acceptance

Fresh account and existing-account augmentation show honest independent capability
outcomes; one provider failing doesn't poison all accounts. Unsupported quota has
no fake0/error bar. Source/date visible, stale status retained honestly. Native
narrow/wide UI + CLI fixture parity; reload/navigation preserves drafts/selection.
No automatic paid probe or key-budget mutation to obtain a green status.

Default-removal/empty-profile policies still conditional in STAB-05; they don't
block the rest of this view. Return source/outcome fixtures, native evidence and
handoffs to STAB-04/05/11, no duplicate implementation or claim every OAuth works.
